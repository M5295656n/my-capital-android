# MyCapital AI — исследование локальных моделей и runtime

Дата: 17 ноября 2026  
Статус: предварительный shortlist; ни одна модель не утверждена для релиза.  
Связанный документ: MYCAPITAL_AI_NEWS_SPEC_RU.md  
Базовая ветка: feature/mycapital-ai-news-analysis-2026-11-17 (PR #90).

## 1. Жёсткие ограничения

- Только on-device inference. Никаких API, backend, cloud inference или платных лимитов.
- Никакой отправки новостей или портфельного контекста внешнему ИИ.
- Загрузка весов — только по явному действию пользователя; до загрузки показать размер, лицензию и требования.
- Не включать модель в APK и не хранить веса в Git.
- Если модель не поддерживается или не проходит проверку памяти/стабильности — использовать маркированный «Автоматический разбор».
- Целевое устройство: Samsung Galaxy A34, SM-A346E. Пользователь подтвердил физическую RAM: 8 ГБ (не RAM Plus). Фактический доступный объём для процесса всё равно измеряется на устройстве во время теста.

## 2. Предварительная матрица моделей

| Модель | Лицензия / язык | Оценка для проекта | Решение |

| Qwen3.5-0.8B | Apache 2.0; компактная мультиязычная модель | Полезна как baseline скорости/простого резюме, но 0.8B нельзя заранее считать достаточной для сценарного анализа, оценки каналов и портфельных последствий | Только контрольный baseline |

Важно: таблица — предварительный отбор по официальным карточкам и доступным форматам, а не сравнительный тест качества. Размеры и требования зависят от конкретной квантизации, длины контекста, KV-cache и runtime.

## 2.1 Уточнение по источнику GGUF и квантизации

Официальная карточка Qwen3-1.7B-GGUF подтверждает Apache-2.0 и совместимость с llama.cpp, но найденная официальная страница не подтверждает наличие официального Q4_K_M файла. Q4_K_M варианты на 1.28 GB обнаружены у сторонних квантовщиков (например, TensorBlock и bartowski). Это не меняет лицензию базовых весов, но добавляет отдельный риск цепочки поставки: сторонний файл нельзя автоматически считать официальным или проверенным производителем.

Для первого теста:
- предпочесть официальный GGUF-файл, если его точная квантизация и размер удовлетворяют тесту;
- если нужен Q4_K_M от стороннего квантовщика, закрепить точный commit/revision, URL файла, размер и SHA-256 в manifest; перед использованием сверить исходную модель и репозиторий квантовщика;
- не загружать файл по плавающему имени latest/main без фиксации revision;
- SHA-256 защищает от повреждения/подмены после фиксации ожидаемого хеша, но сам по себе не доказывает доброкачественность модели.

## 3. Runtime

### llama.cpp (первый кандидат для прототипа)

Важное ограничение официального GUI-примера: examples/llama.android/lib и demo app сейчас выставляют minSdk = 33; библиотека требует minCompileSdk = 35. В MyCapital minSdk = 26, compileSdk = 36. Поэтому нельзя подключать upstream Android library к основному app-модулю без повышения minSdk всего продукта.

Безопасный путь проверки — отдельное standalone benchmark-приложение/модуль с minSdk 33, не включённое в production APK. Основной MyCapital остаётся minSdk 26. После теста можно отдельно решить, как доставлять runtime: условный feature/module с API-level gating, собственная portable NDK-сборка под API 28+ с минимальным Kotlin/JNI bridge, или оставить AI недоступным на старых устройствах. Ни один вариант пока не выбран.

Плюсы:
- поддерживает Android arm64-v8a через Android NDK;
- широко используемый GGUF формат;
- Qwen3 имеет официальный GGUF-вариант и заявленную совместимость с llama.cpp;
- можно ограничить контекст, число потоков и размер генерации, измерять RAM и время.

Риски:
- upstream уже содержит Android Studio пример `examples/llama.android` с Kotlin facade, загрузкой GGUF из `ContentResolver`/private storage и выдачей токенов через Kotlin Flow; нужно изучить и адаптировать, а не писать JNI-обвязку с нуля;
- native runtime всё равно требует аккуратного управления жизненным циклом контекста и памяти;
- CPU/GPU ускорение зависит от устройства и конкретной сборки;
- обновления native runtime требуют регрессионных тестов.

### Google LiteRT-LM (параллельный технический spike)

Плюсы:
- официальный Android/Kotlin путь для локальных LLM;
- управление диалогом, KV-cache и потоковым выводом;
- ориентирован на аппаратное ускорение CPU/GPU/NPU.

Риски:
- нужно проверить доступность готовой конвертации именно выбранной модели и корректность токенизатора/chat template;
- нельзя считать поддержку конкретной модели гарантированной только потому, что runtime поддерживает LLM в целом;
- до успешного прототипа на SM-A346E не выбирать его как production runtime.

### Gemini Nano / AICore

Не использовать как обязательную основу: доступность зависит от модели устройства, версии системных компонентов и capability API. Android 14+ само по себе не гарантирует поддержку. Никаких облачных fallback.

## 4. Предварительное техническое решение

1. Начать с отдельного standalone benchmark app на базе официального examples/llama.android (minSdk 33), без зависимости production app; тестовая модель — Qwen3-1.7B-Instruct GGUF Q4_K_M с зафиксированной версией/хешем.
2. Параллельно проверить LiteRT-LM только как альтернативный runtime, если есть готовая официальная конвертация выбранной модели.
3. Не поднимать minSdk MyCapital выше 26. Тестовый модуль должен быть отдельным приложением/Gradle-модулем и не попадать в основной APK.
4. Конфигурация целевого устройства подтверждена пользователем: 8 ГБ физической RAM. Перед запуском теста дополнительно измерить доступную память и свободное место; физические 8 ГБ не означают, что весь объём доступен процессу модели.
5. Не интегрировать Phi-4-mini до измерения памяти и нагрева на целевом телефоне.
6. Не выбирать Qwen3.5-0.8B для основного анализа без подтверждения качества на русском тест-наборе.
7. Решение о runtime и модели принимать только после теста на реальном устройстве; до этого приложение не должно показывать, что генеративный анализ доступен.

## 5. Обязательный тест-набор качества

Подготовить не менее 20 новостей на русском языке из официальных источников, разделённых по типам:
- решение/сигнал Банка России по ставке;
- инфляция и статистика Росстата;
- бюджет, налоги и госрегулирование;
- отчётность/дивиденды эмитентов;
- санкции/экспорт/сырьевые рынки;
- корпоративные события и раскрытие информации;
- новости, которые выглядят важными, но не имеют доказуемого влияния на портфель.

Для каждой новости заранее подготовить эталонную карту:
- только проверяемые факты и источник;
- допустимые экономические каналы;
- явно недопустимые выводы/выдуманные цифры;
- релевантные и нерелевантные тикеры;
- что можно сказать с низкой/средней уверенностью;
- какие данные отсутствуют.

Оценивать модели вслепую по одной и той же инструкции:
1. Фактическая точность и отсутствие выдуманных цифр.
2. Корректность экономического механизма.
3. Качество позитивного/базового/негативного сценариев.
4. Разделение краткого, среднего и длинного горизонтов.
5. Отсутствие ложных связей с активами портфеля.
6. Валидность структурированного JSON.
7. Качество русского языка и понятность для частного инвестора.

Отдельно измерять на устройстве:
- размер скачиваемого файла и SHA-256;
- пиковую RAM и поведение при нехватке памяти;
- время до первого токена и tokens/sec;
- полное время анализа;
- нагрев и расход батареи на серии запросов;
- стабильность после сворачивания/возврата в приложение;
- возможность отмены генерации и освобождения native-ресурсов.

## 6. Критерии допуска в приложение

Модель не допускается в релиз, если:
- выдумывает данные/источники или регулярно смешивает факт и предположение;
- систематически приписывает новости влияния на не связанные с ней компании;
- не формирует валидный JSON даже после ограниченного повторного запроса;
- вызывает OOM, зависания или недопустимый нагрев на целевом телефоне;
- не имеет ясных условий лицензии для бесплатного распространения/загрузки;
- требует облачной инфраструктуры или отправляет данные с устройства.

Если генеративная модель не проходит критерии, MVP выпускается с честным rule-based разбором, без заявления о наличии ИИ-аналитика.

## 8. Следующий инженерный шаг

Не подключать модель к UI. Сначала создать изолированный Android proof-of-concept/benchmark harness на отдельной feature-ветке, который:
- скачивает/импортирует выбранный GGUF только по явному действию;
- проверяет SHA-256;
- запускает один локальный запрос без сети;
- показывает фактические RAM, время, скорость и ошибки;
- позволяет отменить генерацию и выгрузить модель;
- не читает и не отправляет реальные данные портфеля.

После проверки на Samsung SM-A346E (8 ГБ физической RAM) и слепой оценки качества принять решение о runtime/модели. Любая интеграция в основное приложение — отдельный PR поверх согласованной базовой ветки; main не менять и ничего не объединять без разрешения.
